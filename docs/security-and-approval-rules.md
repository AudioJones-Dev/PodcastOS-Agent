# Security and Approval Rules

## Purpose

Define the safety rules for Podcast OS operators and agents.

## Security Rules

1. Do not add secrets to this repo.
2. Do not paste API keys, passwords, tokens, or credential files into Markdown.
3. Do not publish client files outside approved channels.
4. Do not expose private client materials in public examples.
5. Keep client deliverables inside the client folder unless explicitly linked in the Client Bible.

## Approval Rules

Human approval is required before:

- Accepting a new client
- Finalizing strategy
- Approving topics
- Approving production sheets
- Publishing or scheduling content
- Sending reports
- Changing pricing or contract details
- Editing brand-sensitive claims
- Changing strategic direction

## Publishing Rule

Publishing approval is separate from edit approval. An approved edit does not authorize publishing.

## Client Claim Rule

Claims about results, expertise, compliance, pricing, timelines, or guarantees must be reviewed before public or client-facing use.

## Incident Rule

If sensitive data is accidentally added, stop work, notify the operator, and remove it using an approved remediation path.
